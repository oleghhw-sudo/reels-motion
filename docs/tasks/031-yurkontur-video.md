## Строка спецификации (дефолты архитектора; Олег подтверждает на чекпоинте 1)

Отклонения от reel-presentation записать в брифе явно:

## Визуальный язык: режим `hud`

Референс: `videos/yurkontur/ref/reference.mov` (Олег кладёт файл; 22 с, 1080×1350, 60 fps). Это генеративный HUD одним непрерывным кадром: поле из тысяч тонких линий с яркими пучками, кольцо с моноширинным текстом, живые мини-панели, монохром с одним акцентом.

Что берём:
- один непрерывный кадр на весь ролик; смена глав — движением камеры по схеме, без склеек;
- несколько слоёв движения одновременно (поток частиц, нитки, обновляющиеся панели), плотность растёт к финалу;
- сдержанная палитра с одним акцентом, но в токенах стенда (светлая бумага), а не тёмная тема референса — см. «Палитра и шрифты»;
- моноширинный шрифт для фактуры.

Что не берём:
- декоративные выдуманные данные (в референсе на панели написано «ILLUSTRATIVE / SOURCE CHECK REQUIRED»). У нас любое число — только из NUMBERS_CHECK, любой экран — реальный;
- вспышки, тряску, хроматику, zoom-punch.

Два класса текста:
- читаемый — в `<Readable>`, по нормам 16:9 выше, в кадре один фокус;
- фактура — мелкий моноширинный текст, яркость ≤ 40 %, метка `data-texture` (readcheck пропускает). Содержимое фактуры только настоящее: названия модулей, полей картки, вердиктов, типов документов ланцюга. Никаких выдуманных логов и чисел.

Режим `hud` в светлом варианте: «живий креслярський прилад» — графитовые линии на бумаге вместо светящихся линий на чёрном.

| `--line` / `--line-2` | #DFD7C9 / #D1C7B8 | поле тонких линий (фактура), контуры узлов |

Цветовая логика как в интерфейсе: охра — то, что предложила модель или посчитал код; зелёный — то, что подтвердил человек; красный — конфликт. Других цветов не вводить.

Шрифты стенда: Source Serif 4 (заголовки), Inter (интерфейс, подписи), JetBrains Mono (данные, фактура). Все три под OFL, с украинской кириллицей. Если их нет в `public/fonts` reels-motion — извлечь woff2 из `@font-face` стенда, положить в `public/fonts`, проверить глифы ґ є і ї ’ и записать в манифест с лицензией. Подменять другими нельзя.

Фирменное движение (одно, 3 раза): **«поле картки тягне нитку до свого джерела в скані»**. Блок 2 (ставка → скан), блок 3б (поля картки → разные документы ланцюга), локап (последняя нитка собирает название).

Бюджет ударов: 0 L, ≤ 3 M (вспышка схемы в блоке 2, включение петли в блоке 4, выход на весь механизм в блоке 5).

## Схема архитектуры (по ответу архитектора юрконтура)

```
Основной поток (слева направо):
Скани
 → Розпізнавання тексту + дочитування (печатка, бліде, рукопис → людині)
 → Два незалежні читання (другий агент не бачить першого; словник скорочень)
 → Перевірки кодом (ЄДРПОУ, дати, суми прописом = цифрами, цитата є в скані)
 → Черга перевірки ── ЛЮДИНА №1: критичні значення підтверджує юрист або відділ оренди
 → Розбір ланцюга (договір → допугоди → акти → розірвання; що кожен документ змінює)
 → Картка чинних умов (поле + джерело + місце в скані + дата набрання чинності)
     ├→ Строки (рахують правила, не модель)
     └→ Відхилення від еталона (пункт → смислові твердження → вердикт)
            └── ЛЮДИНА №2: вердикти і конфлікти документів вирішує юрист

Оболонка: усе показується в ALI, модуль «Юр.контур», картка аптеки поруч із плануванням.
ALI для договорів — тільки джерело планувань, сам ALI не змінюється.

Петля навчання (дугою під потоком; «так працюватиме»):
рішення людини (підтвердити / виправити з приміткою)
 → виправлення стає контрольним прикладом
 → щотижневий розбір помилок за типами
 → пропозиція: словник / бібліотека формулювань / навичка читання
 → перевірка на еталоні (тільки для навичок читання)
 → нова версія або відкат

Межа: «юридичні висновки» стоять поза петлею, тільки у людини.
```

Узлы схемы — фактура + подпись (читаемый текст только у активного узла). При заходе камеры узел раскрывается в реальный экран стенда, если экран существует, или в схему, если экрана нет.
