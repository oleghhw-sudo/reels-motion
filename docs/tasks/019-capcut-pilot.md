# 019 — Пилот: Claude Code собирает таймлайн в проекте CapCut (capcut-cli)

Согласовано: Олег «да, пилот CapCut» 2026-10-24. Архитектор. Основание: `docs/CAPCUT-analysis.md`.
Где: **только Mac** (CapCut 9.5.0, медиа). Цель — **проверить гипотезу**, а не строить пайплайн: принимает ли CapCut 9.5 (mac) таймлайн, записанный capcut-cli в пустой проект, и что из записанного переживает открытие/закрытие.

## Перед запуском (делает Олег, не билдер)
1. В CapCut создать **пустой** проект, назвать `Pilot`, ничего в него не класть.
2. Закрыть CapCut полностью (Cmd+Q).

## Ограничения (нарушение = задача отклоняется)
- Писать **только** в папку проекта `Pilot`. Остальные проекты — только чтение; доказать: sha256 всех `draft_info.json` (корень и `Timelines/*/`) остальных проектов до и после — совпадают.
- Перед любой записью — **полная копия** папки `Pilot` в `out/capcut-pilot/backup-<время>/` (`cp -Rp`).
- CapCut во время записи закрыт: `pgrep -x CapCut` пусто.
- capcut-cli **ровно 0.31.1**, ставить локально в `pilot/capcut/` (свой `package.json`, точная версия, `npm install --ignore-scripts`; `node_modules` — в .gitignore). **Не** ставить как плагин Claude Code, **не** `npm i -g`, **не** `npx` без версии.
- **Запрещено:** `caption --cloud`, `translate`, любые команды, идущие в сеть; `init`/`quickstart` (создают новую папку — риск «unusual path»); UI-автоматизация (`export`). Перед работой: grep исходника пакета на `http`/`fetch` — в отчёте перечислить, какие команды ходят в сеть, и подтвердить, что они не вызывались.
- Гейт 2: путь к проектам CapCut — новая переменная `CAPCUT_PROJECTS_DIR` сначала в `env.manifest.json` (+ `.env` Олега; без дефолта в коде). Медиа пилота — в `~/Movies/reels-pilot-media/` (не Desktop/Documents/Downloads — песочница Mac); путь — `CAPCUT_MEDIA_DIR` в манифесте.
- Гейт 5: `outro.yaml` и прочие данные проекта не трогать.

## Шаги
1. `pilot/capcut/` + установка (см. выше). `npx capcut --version` (из локального node_modules) = 0.31.1.
2. **Диагностика (только чтение)** проекта `Pilot`: список файлов, есть ли `Timelines/project.json` и `main_timeline_id`, какой `draft_info.json` авторитетный, `new_version`, `version`. Встроенные `diagnose`/`lint` capcut-cli — без записи.
3. **Каталог ID из кэша Олега:** `harvest-enums` по его 10 проектам (только чтение; sha до/после). В отчёт — какие переходы найдены; для пилота выбрать **один переход, который уже встречается в его проектах**.
4. **Медиа:** скопировать (настоящие файлы, не симлинки) в `CAPCUT_MEDIA_DIR`: 3 клипа аутро MIA — V1 (кадры 180–201), V3 (228–260), V10 (150–193) из `MIA_SHORT_DIR/_outro-analysis/src/` и музыку `MIA_SHORT_DIR/_outro-analysis/music/D_preroll_9hits_42.379-60.720.wav`. Лицензия музыки — как в `outro.yaml` (Suno, предупреждение, гейт 6).
5. **Запись в `Pilot`** (бэкап сделан, CapCut закрыт), с `--active-timeline` (или `sync-timelines --nested`, если так требует документация 0.31.1 для mac — объяснить выбор):
   - дорожка видео: 3 клипа подряд, обрезка по кадрам из шага 4; стыки на долях из `outro.yaml` (`hits` h1 = 0.917 с, h2 = 2.752 с; начало = 0);
   - музыка на всю длину, fade-out 0.3 с в конце;
   - **1 переход** (из шага 3) на стыке клипов 2→3;
   - **1 keyframe-зум** на клипе 2: масштаб 1.00 → 1.12 от начала до конца клипа;
   - `register` материалов, `lint` — без ошибок.
6. **Позитивный контроль (гейт 4):** запустить CapCut (`open -a CapCut`), повторить любую команду записи → capcut-cli **обязан отказать** (CapCut запущен); показать вывод; закрыть CapCut (Cmd+Q / `osascript -e 'quit app "CapCut"'`), убедиться `pgrep` пусто. Плюс: sha256 `Pilot/…/draft_info.json` до и после отказанной команды — совпадают.
7. Снимок записанного: копия всех `draft_info.json` `Pilot` → `out/capcut-pilot/written/`. **СТОП**, отчёт, коммит, push.
