## Сделано
1. **`env.manifest.json`** (гейт 2, до кода):
   - `env.vars`: `GEMINI_API_KEY`;
   - `binaries`: `whisper-cli` (whisper.cpp, MIT, `brew install whisper-cpp`);
   - `data_dirs`: `WHISPER_CPP_MODEL` (путь к ggml-модели) и `ASR_PYTHON` (python окружения с `whisperx==3.8.6`, faster-whisper 1.2.1, torch 2.8.0).
   Всё помечено `required_for: "voice"`. Окружение `.venv-asr/` добавлено в `.gitignore`.
2. **`voice/gemini.mjs`** — клиент без SDK:
   - `listVoices({ search, languageCode, pageSize })` читает все страницы `GET /v1beta/voices`;
   - `tts({ text, voice, model, style })` → `{ wav, sampleRate: 48000, durationSec, meta }`. Модель и голос обязательны. Стиль кладётся в `speech_metadata.style`, только если задан;
   - если пришёл сырой PCM (`audio/L16`) вместо WAV, клиент оборачивает его в WAV по частоте из mimeType;
   - ресемплинг 24 → 48 кГц тем же фильтром swr, что в 002;
   - ошибки 400/401/403/429/5xx выводятся понятным текстом. Повтор только на 429 (5/15/45 с), как в `voice/run.mjs`.
3. **`voice/calibrate.mjs --provider gemini --list [--search <строка>]`** → `out/voice/gemini-voices.json`, плюс сверка с `voice/calibration-gemini.json`. Файл Олега скрипт только читает. Если голос не найден — exit 1.
4. **`voice/align.mjs`**:
   - `align({ wavPath, text, lang, engine })` → `{ words: [{ text, start, end, heard, match, interpolated }], transcript }`;
   - 4 движка: `whispercpp`, `whispercpp-dtw`, `fasterwhisper`, `whisperx`. Python-движки работают через `voice/asr_py.py`;
   - сопоставление `matchScript` — LCS из `metrics.mjs` в каноническом виде:
     - числа 0–999 переводятся в слова;
     - числительные любой формы сводятся к основе («дев’ятої» ↔ «9», «двадцятої» ↔ «20»);
     - род сведён: «одна» → «один», «дві» → «два»;
     - орфография ASR: «ґ» → «г», «й» ↔ «і», «у» ↔ «в».
   - Слово сценария без пары получает время интерполяцией между соседями и `match: false`, а в поле `heard` — что распознано на его месте.
5. **`voice/align.bench.mjs`** — замер точности на эталоне Fish 002 (18 файлов, 171 слово). Сохраняет распознавание (`out/voice/align-raw-<engine>.json`); с `--reuse` пересчитывает сопоставление без повторного ASR. Копия результата — `docs/tasks/data/007-align-bench.json`.
6. **`voice/align.test.mjs`** — позитивный контроль. Чистые проверки без ASR (числа, орфография, интерполяция, критерий точности) и живые проверки движка (+500 мс тишины, вырезанное слово).

## Шаг 4 — точность выравнивания на эталоне Fish (СТОП)
Команды:
```bash
WHISPER_CPP_MODEL=$HOME/.whisper/ggml-large-v3.bin node voice/align.bench.mjs whispercpp,whispercpp-dtw
ASR_PYTHON=$PWD/.venv-asr/bin/python node voice/align.bench.mjs fasterwhisper
ASR_PYTHON=$PWD/.venv-asr/bin/python node voice/align.bench.mjs whisperx
node voice/align.bench.mjs whispercpp,whispercpp-dtw,fasterwhisper,whisperx --reuse   # итоговый пересчёт после правок сопоставления
```
Ошибка начала слова в мс, по словам с `match: true`. Модель large-v3 у всех, CPU (Apple M5, 16 ГБ).
| Движок | Медиана | p95 | Сдвиг (знак. медиана) | Без сдвига: медиана / p95 | Слов сопоставлено | Время на 18 файлов | Критерий |
|---|---|---|---|---|---|---|---|
| whisper.cpp (`-ml 1 -sow`) | 200 | 666 | −190 | 183 / 480 | 144/171 | 57 с | FAIL |
| whisper.cpp + DTW (`-dtw large.v3 -nfa`) | 80 | 277 | +80 | 60 / 226 | 144/171 | 83 с | FAIL |
| faster-whisper (`word_timestamps`) | 120 | 480 | −120 | 80 / 360 | 140/171 | 165 с | FAIL |
| WhisperX (wav2vec2 `Yehor/wav2vec2-xls-r-300m-uk-with-small-lm`) | **75** | **228** | +66 | **36** / 244 | 139/171 | 289 с | FAIL |

Критерий: медиана ≤ 33, p95 ≤ 100. Не прошёл никто. Лучший по медиане — WhisperX. Ни у кого нет p95 ≤ 100 мс даже после вычета постоянного сдвига.

### Что важно знать про эталон и цифры
- **Эталон Fish сам квантован с шагом 80 мс**: все 342 значения start/end в 18 файлах кратны 80 мс. Это даёт ±40 мс погрешности самого эталона. Идеальный выравниватель покажет против него медиану около 20 мс и p95 около 38 мс, так что критерий 33/100 достижим. Но к медиане любого кандидата примешаны до 40 мс шума эталона.
- Знак сдвига у кандидатов разный (−190, −120, +66, +80 мс). Значит, это не общий сдвиг эталона, а собственная систематика каждого движка.
- **Контроль +500 мс на WhisperX** (не зависит от качества эталона): 7 слов из 9 сдвинулись на 510–521 мс, то есть собственная повторяемость +10…21 мс. Но «24» и «години» уехали на 728 и 841 мс. Причина: Whisper пишет числа цифрами, wav2vec2 цифры не выравнивает (в словаре модели их нет), и время «24» интерполируется от начала файла. На словах без цифр WhisperX точен, и это одна из причин его хвоста p95.

### Несовпадения слов (`match: false`) — гипотезы для уха, одинаковы у всех движков
Список лучшего по точности (WhisperX), 32 слова. Полные списки по каждому движку — в `docs/tasks/data/007-align-bench.json`:
- **Голос 8221c35c («Молодий жіночий голос»)** — больше всего, по 4 фразы подряд: «Погляд, який говорить більше» → «Поглядіть… вабарит теж»; «7 днів на тиждень» → «Всім днім надіжди»; «сім» → «8». Это совпадает с твоей оценкой этого голоса на слух.

## Варианты решения (для архитектора и Олега, не сделано)
1. **Лучший эталон.** У Fish шаг 80 мс. Ручная разметка 2–3 фраз по осциллограмме (Audacity) с точностью ~10 мс покажет, сколько ошибки WhisperX даёт сам эталон.
2. **WhisperX + цифры словами до выравнивания.** Переписывать транскрипт Whisper («24» → «двадцять чотири») перед wav2vec2 — это уберёт главный выброс. Хвост p95 придётся мерить заново.
3. **Принудительное выравнивание по тексту сценария,** а не по распознанному (wav2vec2 CTC по известному тексту). Тайминги станут точнее, но проверку произношения придётся делать отдельно — через распознавание с `match`.
4. **Пересмотреть критерий** с учётом погрешности эталона (например, медиана ≤ 40, p95 ≤ 150) — если для подсветки слов в роликах этого достаточно. Решать Олегу.
