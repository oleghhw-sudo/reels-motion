# Задачи: архитектор → билдер

**Архитектор** — Claude в облачном чате с Олегом: анализ, архитектура, ТЗ, ревью. Код проекта не пишет.
**Билдер** — Claude Code на Mac Олега, рабочая папка `~/Projects/reels-motion`: реализация, проверки, рендер.

## Цикл

1. Архитектор кладёт задачу `docs/tasks/NNN-<slug>.md` и пушит в `main`.
2. Олег: `git pull` → в чате Claude Code: «выполни задачу docs/tasks/NNN-<slug>.md».
3. Билдер выполняет ТОЛЬКО то, что в задаче. Вне рамок — не делает, а пишет в отчёт «предложения».
4. Билдер пишет `docs/tasks/NNN-<slug>.report.md` по шаблону ниже, коммитит код + отчёт одним коммитом
   `task NNN: <кратко>` и пушит в `main`.
5. Архитектор делает `git pull`, ревьюит код и отчёт, ставит в задаче статус `done` или пишет `NNN-<slug>.review.md` с правками.

## Правила билдера (кроме CLAUDE.md)

- Задача — источник истины. Неясно или противоречит CLAUDE.md → остановиться и спросить Олега, не угадывать.
- Полный рендер видео — только если задача прямо требует, и один раз в конце. Проверки — stills, readcheck, аудио отдельно.
- Каждая проверка в отчёте — с командой и фактическим выводом (числа), без «должно работать».
- Позитивный контроль для каждой новой проверки (гейт 4).
- Ориентир времени задачи указан в ней; превышение больше чем вдвое — остановиться и сообщить причину.

## Шаблон отчёта

```markdown
# Отчёт: NNN-<slug>
Статус: готово | частично | заблокировано
Время: … мин
## Сделано
## Файлы (новые / изменённые)
## Проверки (команда → результат)
## Отклонения от задачи и почему
## Предложения (вне рамок задачи, не сделано)
```
