# 007 — Голос Gemini TTS + выравнивание слов по аудио

## Почему
Калибровка 002: Fish на украинском не годится (ошибки, «не похоже на украинский» — оценка Олега на слух).
Олег прослушал в AI Studio `gemini-3.8-flash-tts`, голос Gero: «естественное звучание, максимально корректно».
Украинского нет в официальном списке языков Gemini API для 3.8, поэтому решает только эталон и слух, не документация.

У Gemini TTS **нет таймингов слов** — только аудио (WAV, 24 кГц, моно, 16 бит). Тайминги даёт отдельный шаг:
распознавание готового аудио на Mac + сопоставление со сценарием. Этот шаг не зависит от провайдера голоса
и даёт то, чего не было у Fish: **проверку произношения** (слово не распознано как написанное → флаг).

## Секреты
- Новый ключ `GEMINI_API_KEY` — сначала в `env.manifest.json` → `env.vars` (`required_for: "voice"`), потом в коде (гейт 2).
- Ключ вводит Олег сам (скрытый ввод в `.env`). Билдер `.env` не читает и не печатает; в логах — «задан/не задан».
- Запуск: `node --env-file=.env …`.

## Источник истины по API (проверить по документации перед кодом, сверить с живым ответом)
https://ai.google.dev/gemini-api/docs/generate-content/speech-generation
- `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash-tts:generateContent`, заголовок `x-goog-api-key`.
- Тело: `contents[].parts[].text` (текст дословно), `speech_metadata.style` (стиль, необязателен),
  `generationConfig.responseModalities: ["AUDIO"]`, `generationConfig.speechConfig.voiceConfig.voice: "<имя>"`.
- Ответ: `candidates[0].content.parts[0].inlineData.data` — base64 WAV (RIFF), 24 кГц.
- Список голосов: `GET /v1beta/voices` (фильтры `language_code`, `gender`, `search`, `page_size`).
- Google советует: стиль сначала пустой; акцент/возраст/пол в стиль не писать (голос «плывёт»).
Расхождение документации с живым ответом — записать в отчёт и следовать живому ответу.

## Что сделать

### Часть А — провайдер и выравнивание (без прогона калибровки)

1. `voice/gemini.mjs` — клиент без SDK.
   - `listVoices({ search?, languageCode?, pageSize })` → имя, описание/теги, пол, если есть.
   - `tts({ text, voice, model, style })` → `{ wav: Buffer, sampleRate, durationSec, meta }`. Модель и голос передаются явно (гейт 2, без значений по умолчанию).
   - Ошибки 400/401/403/429/5xx понятным текстом; 429 — повтор с паузами (как в `voice/run.mjs`), остальные — без повторов.
   - WAV 24 кГц → 48 кГц тем же ресемплером, что в 002 (`aresample=48000:resampler=swr:filter_size=64:phase_shift=10:cutoff=0.97`).
2. Проверить, что голоса из `voice/calibration-gemini.json` существуют в `listVoices` (Gero виден в AI Studio, но в списке 30 стандартных голосов документации его нет — возможно, это расширенная библиотека). Голоса нет → СТОП, в отчёт — что нашлось по поиску.
3. `voice/align.mjs` — выравнивание: `align({ wavPath, text, lang: 'uk' })` → `{ words: [{ text, start, end, heard, match }], transcript }`.
   - Распознавание с таймингами слов локально на Mac. Кандидаты (выбрать по измерению, не по описанию): whisper.cpp с таймингами слов; faster-whisper `word_timestamps`; WhisperX (выравнивание wav2vec2 для украинского). Новая зависимость (бинарь/модель/pip) — в `env.manifest.json` с подсказкой установки.
   - Сопоставление распознанных слов со словами сценария — LCS из `voice/metrics.mjs` (`tokenize`, `diffWords`). Слово сценария без пары → время интерполируется между соседями, `match: false`.
   - `match: false` = подозрение на ошибку произношения ИЛИ ошибку распознавания. Это гипотеза для уха Олега, а не вердикт.
   - Цифры: сценарий «24» ↔ распознанное «двадцять чотири» — нормализовать числа в слова для сравнения (минимум 0–100), иначе фраза 6 всегда «красная».
4. **Измерение точности выравнивания до выбора кандидата (эталон с известной правдой):**
   - Эталон — аудио Fish из 002 (`out/voice/<slug>/<n>.wav` + `<n>.words.json`): у Fish тайминги от самой модели. Прогнать каждого кандидата на этих 18 файлах, посчитать отклонение начала слова: медиана и 95-й перцентиль, мс.
   - Критерий: медиана ≤ 33 мс (один кадр 30 fps), p95 ≤ 100 мс. Не прошёл ни один — СТОП, цифры в отчёт.
   - Позитивный контроль: тот же файл со вставленными 500 мс тишины в начале → все слова сдвинуты на 500 ± 33 мс; файл с вырезанным словом → это слово `match: false`. Испорченный эталон обязан дать красное (`--negative`, exit 1).
5. `voice/calibrate.mjs --provider gemini --list [--search <строка>]` — список голосов в `out/voice/gemini-voices.json` (бесплатно).

Отчёт части А → push → СТОП (Олег вводит ключ, создаёт `voice/calibration-gemini.json`, если ещё не создан).

### Часть Б — калибровка Gemini

6. `voice/calibrate.mjs --provider gemini --run`:
   - голоса из `voice/calibration-gemini.json` (создаёт ОЛЕГ, скрипт только читает) × 6 фраз `voice/phrases.uk.json` × **2 дубля** (синтез недетерминирован — нужен разброс), стиль пустой;
   - на каждый файл: `align` + метрики `voice/metrics.mjs` (паузы, темп cps/wpm, конец, LUFS/true peak) + доля `match: false` и список несовпавших слов (написано → услышано).
   - `out/voice/gemini/<voice>/<n>-<take>.wav` + `.words.json`; `listen.html` с подсветкой (тот же генератор, что в 002).
7. `out/voice/metrics.json` по схеме 002 + поля `provider` (`"fish"|"gemini"`), `take`, `asr: { engine, matchRate, mismatches: [{ said, heard }] }`. Копия — `docs/tasks/data/007-metrics.json`. Данные 002 не перезаписывать.
8. Бесплатный тариф Gemini API. Перед прогоном — один пробный запрос, ответ (статус, формат, длительность) в отчёт. Платный тариф не включать.
