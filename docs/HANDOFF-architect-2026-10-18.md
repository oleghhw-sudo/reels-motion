# Передача архитектору (Claude Opus 5.5): что изменено 2026-10-18 и как продолжать

Кому: архитектор проекта (облачный чат, Opus 5.5). От кого: облачная сессия Claude Code (ветка `claude/exciting-hamilton-t42s0r`, модель Fable 5.1). Заказчик правок: Олег.
Запрос Олега, дословно по смыслу: «прошерстить скиллы, найти ошибки, чтобы motion был живым, пластичным, активным, не банальным; посмотреть опыт Opus 5.5 в визуале/рендере/motion; добавить эффекты уровня After Effects и постобработки; посмотреть стили, которые заходят; записать задумку «искажение реальности» как вариант; затем — перепроверить с полным доступом к сети и сделать этот файл».

Ничего из `src/`, `videos/`, `approved/`, `sfx/`, `env.manifest.json`, `package.json` **не менялось**. Все правки — документы, скиллы и задачи. Код по гейту 7 и протоколу ролей — за билдером после «да» Олега.

## 2. Приоритеты между скиллами (как теперь читать)
1. Гейты CLAUDE.md (как и раньше) → 2. номера motion-prompt, выбранные Олегом (ровно по спецификации) → 3. readcheck для текста → 4. **режим брифа** решает, действует ли living-motion §12 целиком (editorial) или cinematic-fx §1 (доза) → 5. физика движения (living-motion §1–§11) одинакова во всех режимах → 6. beat-sync ставит удары и склейки на сетку, карта ударов брифа задаёт размер S/M/L → 7. motion-review проверяет движение (лист удара, энергия), не только стиллы.
Исключения стиля записываются в бриф (пример: Swiss-стиль разрешает eyebrow-метки «01 / 06», запрещённые §12).

## 5. Известные несоответствия и риски (не исправлены намеренно — вне рамок/требуют кода)
- **`src/videos/mia-outro/model.ts` не знает `outro.yaml` v2** (`in`, `ramp`, `music.holdAfter`, блок `sfx` с `pick`): `parseOutro` упадёт на `sfx`. Это ожидаемо (данные опередили код), но значит, что `MiaOutro` сейчас не собирается — пока билдер не сделает 008 v2 (схема расширяется в 012-Б или 008 v2 — решить в задаче, чтобы не делать дважды).
- **`@remotion/effects` в Studio** требует Chrome ≥ 149 с флагом `canvas-draw-element` для `HtmlInCanvas`; headless-рендер с 4.0.534 — без настроек. Билдер может увидеть пустой слой в Studio — проверять стиллами.
- **Долги 011-А** остаются: две сетки долей (`index.ts gridFromBeat` vs `sync.ts`), две системы кривых, линт сырых чисел — 015 просит минимальный линт.
- **Числа** в cinematic-fx §3 и STYLES §1 — гипотезы из практики AE/CapCut и тренд-отчётов; подтверждены только параметры API (по `.d.ts`) и числа ROOK (прототип). Калибровать на FxLab/StyleLab и эталонах Олега.
- **living-motion §12 vs Swiss-стиль** (eyebrow-метки) — разрешать явно в брифе/реестре стилей.
- **CLAUDE.md** изменён одной строкой; если архитектор ведёт CLAUDE.md как свой файл — проверить формулировку.

## 6. Как продолжать (предложение)
1. Ревью этого набора: прочитать cinematic-fx целиком (это главный новый документ), затем diff living-motion/reel-director/motion-review. Если что-то противоречит вашему видению — править скиллы, не код.
2. Получить от Олега решения §4; положить «да» в задачу 012 (статус open → согласовано) и дать билдеру команду `выполни задачу docs/tasks/012-fx-kit.md` (Opus 5.5).
3. После 012-А — 008 v2 (аутро на `src/fx`), лист удара и energycheck в отчёте; показ Олегу.
4. Параллельно 013 (файлы не пересекаются с 012).
5. Эталоны: попросить у Олега референсы; критик измеряет (cuts/s, zoom, субтитры, музыка под голосом) и калибрует §1–§3 cinematic-fx.
6. 015 (стили) после 012; 014 — когда есть `words.json` (007-Б).
7. 016 — по отдельной команде Олега, после 012.
