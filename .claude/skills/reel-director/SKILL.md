# reel-director — с чего начинается ролик

Билдер работает только по задаче `docs/tasks/NNN-*.md` (CLAUDE.md, «Роли»). Этот скилл — порядок действий внутри такой задачи.

## 1. Определить тип
| Признак материала и цели | Тип | Ведущий скилл |
|---|---|---|
| Видеофайлы с сюжетом/персонажами; трейлер, аутро, интро серии, знакомство с героями, тизер | **кинематографичный** | reel-cinematic |
| Графика, интерфейс, текст, числа, голос диктора; промо курса/продукта, объяснялка, кейс, инфографика | **презентационный** | reel-presentation |
| Видео-фон/вставки + рисованная графика и текст поверх (промо курса с кадрами работ, кейс клиента с видео) | **гибрид** | reel-presentation (структура) + reel-cinematic (работа с видео) |
Всегда добавляются: **living-motion** (любая графика и текст «живые»), **beat-sync** (если есть музыка/SFX), **motion-review** (перед показом и финалом). Именованные движения — **motion-prompt** (номера от Олега переносятся ровно). В режимах cinematic и punch (ниже) — обязательно **cinematic-fx** (приёмы AE-словаря, анатомия удара, финишная обработка, дозировка).

## 1а. Определить режим выразительности (living-motion §−1)
| Режим | Когда | Ведёт |
|---|---|---|
| **editorial** | бренд-ролик по сайту клиента, спокойная презентация, UI-демо; «дорого = сдержанно» | living-motion §12 целиком |
| **cinematic** | трейлер, аутро, титры, герои, тизер из видео — всё, где удар, камера и пост-обработка несут смысл | cinematic-fx (аутро MIA v2 — эталон) |
| **punch** | динамичная объяснялка/промо под бит, говорящая голова с субтитрами по словам, кейс с цифрами | cinematic-fx (таблица режимов) + reel-presentation |
Сомнение между editorial и punch — спросить Олега, показав два стоп-кадра одной сцены в обоих режимах. Режим пишется в строку спецификации брифа и читается всеми скиллами.

## 2. Бриф → `videos/<id>/brief.md`
- Строка спецификации: `1080x1920@60, 30s, 120BPM, pace: calm|crisp, type: cinematic|presentation|hybrid, mode: editorial|cinematic|punch, audio: <трек/нет>, voice: <провайдер/голос/нет>, lang: uk|en` (fps: презентация 60, кино — fps исходника).
- **Фирменное движение** (одно на ролик, ровно 3 раза: начало, середина, конец — living-motion §10) и **бюджет ударов** (сколько «больших» ударов с impact-кадром/вспышкой — cinematic-fx §3 по режиму) — записать явно.
- **Эталоны:** 2–3 ссылки/файла референсов Олега с таймкодом и одной строкой «что берём» (ритм, удар, субтитры, грейд). Нет эталона — так и написать; тогда числа скиллов — гипотеза, и первый черновик сравнивается с ближайшим утверждённым роликом проекта (аутро MIA v2 для cinematic, beauty-studio для editorial).
- **Финишная обработка** (`look`: грейд, зерно, виньетка, хроматика на краях, letterbox) — выбрать пресет cinematic-fx §5 или «нет».
- Цель и зритель одной фразой; площадка (Reels/Shorts/YouTube 16:9); длина серии, если это аутро.
- Источник бренда: `brandSurface` (сайт клиента) или пресет; исключения из запретов living-motion §12 (если бренд использует, например, бежевый или антикву) — записать явно.
- Запреты сюжета (спойлеры) и запретные зоны материала — для кино.
- Лицензии музыки/звуков — записать; ограничения — предупреждение Олегу (гейт 6).
- Чего нет в задаче — не делать.

## 3. Вопросы Олегу (только то, что меняет работу; остальное — разумный дефолт с пометкой в брифе)
Тип и площадка; **режим** (editorial / cinematic / punch) и 2–3 эталона; длина; музыка (свой трек / подобрать / без); голос (Gemini-голос/клон/без) и язык; темп calm или crisp; субтитры по словам (стиль: тихие / «hormozi» / без); обязательные кадры/тексты/факты; что нельзя показывать.

## 4. Чекпоинты (стоп и показ Олегу)
1. Бриф + бит-лист (таблица такт/время/картинка/текст/звук) + **карта ударов** (какой удар какого размера: S/M/L по cinematic-fx §3).
2. 3 стоп-кадра стиля (крючок, ключевая сцена, кульминация/локап) + фон (BackgroundPicker) или лист кандидатов кадров (HEROES.png) для кино. В cinematic/punch — ещё **лист одного удара** (−4…+8 кадров через кадр) по самому важному удару: подвод, кадр удара, отдача видны по кадрам, а не по описанию.
   2а. **Прототип удара свободной рукой** (cinematic/punch; опыт Opus 5.5, прототип ROOK): один удар или одна сцена 2–4 с рендерится без ограничений скиллов — любым быстрым способом (Python/PIL по кадрам, Remotion-черновик, даже без `src/motion`), с полным словарём AE (cinematic-fx §3), 2–3 варианта по силе. Олег выбирает глазами; выбранное переносится как спецификация (числа по кадрам → пресеты `src/fx`, живой прототип — в `docs/tasks/data/`). Прототип в проект не идёт; его числа — да. Цель: планку задаёт лучший кадр, а не список запретов.
3. Черновик в половину разрешения **+ кривая энергии** (motion-review: `energycheck`) — мёртвые участки и попадание пиков в доли видны до просмотра.
4. Финальный рендер — один раз, на Mac.

## 5. Порядок данных
`brief.md` → `scenes.yaml` (невосстановимое: человек правит, билдер предлагает рядом) → голос + `words.json` (align) → `beats.json`/`edit.json` (beat-sync) → `timeline` (кадры из данных) → сцены → проверка → рендер → мастеринг −14 LUFS.

## 6. Экономия
Анализ видео — листами 4×4, ≤ 2 кадров/с, измеримое — командами. Стоп-кадры вместо рендеров. Субагенты — для параллельной реализации независимых сцен и для критиков.
